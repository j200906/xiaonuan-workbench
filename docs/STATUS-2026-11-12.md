## 一、它是什么（一句话）

小暖是一个**没有传统服务器**的 AI 工作台：前端是纯静态页面，后端由 Cloudflare 的边缘函数提供，
另外附一个零依赖的 Python 后端可以本地跑（同一个前端，两套后端同一份契约）。

## 二、配置现状

### 2.1 模型与后端

| 项 | 当前值 | 说明 |
|---|---|---|
| 后端类型 | `workers-ai` | Cloudflare Workers AI 绑定，**不需要用户自带 Key** |
| 云端模型 | `@cf/zai-org/glm-4.7-flash`（显示名 GLM-4.7-Flash） | 云端唯一可选模型 |
| 备用线路 | 用户自带 Key 直连服务商（默认 DeepSeek） | 填了自己的 Key 就走自己的 |
| 代理模式 | `proxy: true`，前端 `baseUrl=/api` | 自动探测，无 Key 时自动切到服务端代理 |
| 自迭代 | 需要服务端模型 Key；未解锁只给试运行 | 管理员密码门后 |
| 网关（实验） | `https://eyed-permalink-unexpected-loops.trycloudflare.com/v1` | **已死**（DNS 都解析不到），配置待清理 |

### 2.2 能力层

插件宿主提供 4 个可替换能力：`llm` / `fetch` / `search` / `storage`，四个当前都 ready。
搜索走 `XN_TOOLS`（DuckDuckGo + Bing 抓取），抓网页走 `/api/fetch`（带 SSRF 防护）。

### 2.3 插件与视图

- 已注册插件 **8 个**：6 个视图（study / feedback / settings / changelog / iterate / chat）+ 插件中心 + 导出会话
- 侧栏可见入口 **5 个**：对话 / 学习台 / 更新日志 / 插件中心 / 设置
  （反馈箱与迭代按设计收进「设置」与「管理员门后」）
- 插件中心：官方索引 1 个源、**1 个可安装插件**（DSH 示例）

### 2.4 国际化

- 三语：简体中文 / 繁體中文 / English
- 词条：**235 键 × 3 语**，缺键会显示原文（有单测保证三语键集一致）

### 2.5 安全配置

| 项 | 状态 |
|---|---|
| CSP | 响应头 + `index.html` meta 双份：`script-src 'self'`、`object-src 'none'`、`base-uri 'none'` |
| 插件地址策略 | 只允许 http(s)、默认同源、跨源需 `pluginTrustedHosts` 白名单 |
| SSRF 防护 | 解析后判内网（含十进制/十六进制/八进制/IPv6/云元数据），10 项红队全拦 |
| 鉴权 | 管理令牌 HMAC 自签；`/api/iterate` 未解锁只试运行 |
| 限流 | 内存态（单实例有效） |

### 3.4 「服务器」到底是什么

没有一台属于我们的服务器。资源占用实际落在这些地方：

| 资源 | 用量 | 说明 |
|---|---|---|
| Cloudflare Pages | 静态托管 585 KB | 免费额度内 |
| Pages Functions | 每次请求执行 32.8 KB 脚本 | 免费额度 10 万次/天 |
| Workers AI | 按 token 计费 | 免费额度每天一定量神经元 |
| KV | 1 个命名空间 `xiaonuan-feedback` | 存反馈；**当前无法读取条目数**（CF 令牌 401） |
| GitHub | 仓库 + Actions + Release | 免费额度内 |

## 五、发展建议

### 5.1 立刻做（本周，成本低收益高）

1. **换 Cloudflare API Token**，把部署从「等人工授权」变成自动化。这是当前最大的效率瓶颈。
2. **清理死网关配置**，让 `/api/config` 回到干净状态。
3. **把两个线上 bug 写进 ui-check**（入口可见、从索引安装），让测试能抓住同类问题。
4. **插件索引补到 3–5 个官方插件**（比如：番茄钟、错题本、导出 PDF），让插件中心不是空货架。

### 5.2 一两个月内

5. **插件权限模型 + SRI**：安装时声明「需要 llm / 需要 storage」，跨源插件必须带哈希；
   信任域名降级为「允许安装」，而不是「允许任意代码」。
6. **限流换 Durable Object 或 KV**，支持多实例；顺便加「按用户配额」。
7. **两套后端抽公共契约**：把路由表、鉴权、SSRF 规则写成一份 JSON/YAML，两边各自生成，
   现在靠人肉同步太脆。
8. **CI 里跑真浏览器 e2e**（headless），把「首屏无报错、7 视图可达、插件装得上」变成门禁。

### 5.3 三到六个月

9. **模型路由层**：多模型（GLM / DeepSeek / 本地 Ollama）+ 失败自动切换 + 成本上限，
   现在「云端唯一」是单点。
10. **数据同步**：会话目前只在 localStorage，换设备就没了；可以做「可选登录 + 端到端加密同步」。
11. **商业化的最小闭环**：License 校验（离线签名）+ 用量计量 + 私有部署包（exe 已经有了）。

### 5.4 不建议做的事

- 不建议为了「像 DSH」去追 cordis 的依赖注入容器：小暖的插件模型是「视图 + 能力」，
  复杂度不在一个量级，硬套只会引入不理解的概念。
- 不建议现在做多租户：没有登录体系，多租户会先把安全问题放大十倍。

## 六、一句话总结

**代码不大（约 2 万行、静态站 585 KB、exe 11.7 MB），架构是干净的边缘无服务器；
真正拖后腿的不是功能，是运维自动化（CF 令牌）和测试覆盖（线上 bug 靠人眼）。
把这两件补上，这个项目就具备持续迭代的商业底子了。**
